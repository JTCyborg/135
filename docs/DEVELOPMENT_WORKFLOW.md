# Разработка и синхронизация Project135

## Единственный источник исходников

Основная ветка проекта: `main` в GitHub — https://github.com/JTCyborg/135.

Изменения, которые выполняются через ChatGPT, вносятся непосредственно в репозиторий и фиксируются коммитами. После коммита нужно синхронизировать локальную копию через Git Pull / Sync. Передавать исходные файлы в чат не требуется.

ChatGPT не видит незакоммиченные изменения на локальном компьютере. Если локально менялись исходники, сначала сделайте Commit + Push в GitHub. После этого можно попросить проверить проект — достаточно указать ветку и, при необходимости, SHA коммита.

## Локальная копия

Рабочий каталог разработчика: `C:\Temp\trdos\135`.

Рекомендуемый цикл:

1. Перед началом работы выполнить Pull / Sync из `origin/main`.
2. Открыть корневую папку проекта в Visual Studio 2026.
3. Дождаться завершения CMake Configure.
4. Выбрать нужную конфигурацию Debug или Release и собрать проект.
5. Если в локальной копии появились собственные изменения — Commit + Push.
6. Полученные от ChatGPT коммиты забрать через Pull / Sync.

Не копируйте отдельные файлы поверх локальной копии вручную: используйте Git, чтобы сохранялась история изменений и не возникали расхождения.

## Visual Studio 2026 и CMake

Проект использует общий для команды файл `CMakePresets.json`. Он содержит конфигурации Debug/Release и desktop-варианты.

Visual Studio должна использовать CMake Presets:

- Tools → Options → CMake → General.
- Включить использование `CMakePresets.json` для конфигурации, сборки и тестирования (если такой переключатель доступен в установленной версии).
- Закрыть и заново открыть папку проекта после изменения этого параметра.
- Выбирать desktop preset для сборки приложения:
  - `vs2026-desktop-debug`
  - `vs2026-desktop-release`

Qt 6 для MSVC обнаруживается из стандартного каталога `C:\Qt\*\msvc2022_64`. Если Qt установлен в другом месте, путь задаётся локально через `Qt6_DIR` или `P135_QT6_ROOT`; такие локальные пути не должны попадать в общий репозиторий.

## Что не коммитить

Локальные файлы и артефакты сборки исключены через `.gitignore`:

- `.vs/` — кэш и состояние Visual Studio;
- `out/`, `build/`, `cmake-build-*/` — генерируемые каталоги сборки;
- `CMakeUserPresets.json` — персональные настройки разработчика.

Пустой или повреждённый файл схемы Visual Studio в профиле пользователя AppData не является исходником проекта и не должен добавляться в Git. В репозитории хранятся только общие настройки и исходный код.

## Правило работы над проектом

Перед изменением кода сначала проверять актуальное состояние `main`. Все согласованные изменения исходников, CMake, документации и конфигурации коммитить в GitHub. В ответе указывать:

- что изменено;
- SHA коммита;
- какие проверки реально выполнены;
- что нужно сделать локально (обычно только Pull/Sync и Configure/Build).

Не утверждать, что сборка прошла, если она не запускалась в соответствующем окружении.
