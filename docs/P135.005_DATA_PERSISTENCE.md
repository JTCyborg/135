# P135.005 — Calculation Snapshot Persistence

## Status

SQLite migration 002 and the infrastructure persistence API are implemented.

## Calculation snapshot

A calculation snapshot stores:
- stable calculation and project IDs;
- project name and product family;
- canonical input JSON;
- canonical result JSON;
- canonical engine-version JSON;
- SHA-256 over the canonical object containing engine versions, inputs and results;
- author and UTC creation timestamp.

Snapshots are append-only. SQLite triggers reject UPDATE and DELETE.

## Exact material references

```cpp
recordCalculation(calculation, materialReferences);
```

The operation validates all material revision IDs and writes the calculation, all material_usage rows and the audit event in one SQLite transaction. Any invalid revision or duplicate insert rolls the whole transaction back.

```cpp
findCalculation(calculationId);
calculationMaterials(calculationId);
```

These APIs return the immutable calculation payload and the exact material revision IDs used. They do not silently substitute latest material revisions.

## Migration

Desktop startup applies migrations 001_initial_schema.sql and 002_calculation_snapshots.sql.

The second migration adds a trigger requiring calculation usage rows to reference an existing calculation.

## Limitations

- The desktop Calculate workflow automatically creates a snapshot after a successful calculation, including network/filter inputs, harmonic spectrum, thermal settings, displayed result rows, selected material revision IDs and declared engine versions.
- No calculation history/replay UI is implemented yet. Project IDs are currently generated for the desktop session; project save/load and stable project identity across restarts are future work.
- Algorithm identifiers are supplied by the caller; automatic build/commit provenance is not yet injected.
- Replay currently means retrieving immutable inputs, outputs, engine versions and exact material revision references. Deterministic re-execution and comparison are future work.


## Desktop calculation history

The Calculation history tab lists saved snapshots with text search over calculation ID, project name, product family and author. Results are ordered newest first and capped at 500 rows in the current UI.

Selecting a row displays the canonical input JSON, result JSON, engine versions, content hash and exact material revision metadata. The UI resolves every referenced revision by its stored revision ID; it never substitutes the latest revision.

**Load selected inputs into editor** restores the saved network/filter settings, harmonic spectrum, thermal inputs, project identity and exact component revision selections. Historical revisions are inserted into the selectors when necessary. Missing revisions are reported and are not silently replaced. Loading does not execute a calculation; the user reviews the restored inputs and explicitly invokes Calculate. The new run creates a new snapshot and leaves the original immutable.

The active project ID, name and product family are persisted in QSettings across desktop restarts. A project ID is regenerated when the user chooses New project.


## Frequency response data and graph comparison (D43)

New calculation snapshots include raw frequency-domain point arrays in result JSON:

- `frequencySweep[]`: `frequency_Hz`, `bankCurrent_A` from the 151-point logarithmic AC circuit sweep.
- `impedanceScan[]`: `frequency_Hz`, `busImpedance_Ohm`, `filterImpedance_Ohm`, `sourceImpedance_Ohm` from the 501-point logarithmic impedance scan. This series is empty when source R/L is not supplied or the impedance scan is not verified.

The desktop Calculation page plots filter-bank current and bus impedance against logarithmic frequency. The Calculation history table supports selecting exactly two snapshots; the comparison control overlays their selected metric on common axes and includes both snapshot identifiers in the legend. Metrics can be switched between bank current and bus impedance without recomputing either design.

Snapshots created before D43 do not contain frequency point arrays. They remain readable, but graph comparison reports that curve data is unavailable rather than reconstructing or inventing samples. All stored values are numeric SI values with frequency in hertz, current in amperes and impedance in ohms.
