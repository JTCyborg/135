# P135.005 — Calculation Snapshot Persistence

## Status

SQLite migration 002 and the infrastructure persistence API are implemented.

## Calculation snapshot

A calculation snapshot stores:
- stable calculation and project IDs;
- project name and product family;
- canonical input JSON;
- canonical result JSON;
- canonical engine-version JSON;
- SHA-256 over the canonical object containing engine versions, inputs and results;
- author and UTC creation timestamp.

Snapshots are append-only. SQLite triggers reject UPDATE and DELETE.

## Exact material references

```cpp
recordCalculation(calculation, materialReferences);
```

The operation validates all material revision IDs and writes the calculation, all material_usage rows and the audit event in one SQLite transaction. Any invalid revision or duplicate insert rolls the whole transaction back.

```cpp
findCalculation(calculationId);
calculationMaterials(calculationId);
```

These APIs return the immutable calculation payload and the exact material revision IDs used. They do not silently substitute latest material revisions.

## Migration

Desktop startup applies migrations 001_initial_schema.sql and 002_calculation_snapshots.sql.

The second migration adds a trigger requiring calculation usage rows to reference an existing calculation.

## Limitations

- The desktop Calculate workflow automatically creates a snapshot after a successful calculation, including network/filter inputs, harmonic spectrum, thermal settings, displayed result rows, selected material revision IDs and declared engine versions.
- A history browser and input restoration workflow are implemented. Deterministic re-execution and full project file save/load remain future work.
- Algorithm identifiers are supplied by the caller; automatic build/commit provenance is not yet injected.
- Restoration means retrieving immutable inputs, outputs, engine versions and exact material revision references. Deterministic re-execution remains future work.


## Desktop calculation history

The Calculation history tab lists saved snapshots with text search over calculation ID, project name, product family and author. Results are ordered newest first and capped at 500 rows in the current UI.

Selecting a row displays the canonical input JSON, result JSON, engine versions, content hash and exact material revision metadata. The UI resolves every referenced revision by its stored revision ID; it never substitutes the latest revision.

**Load selected inputs into editor** restores the saved network/filter settings, harmonic spectrum, thermal inputs, project identity and exact component revision selections. Historical revisions are inserted into the selectors when necessary. Missing revisions are reported and are not silently replaced. Loading does not execute a calculation; the user reviews the restored inputs and explicitly invokes Calculate. The new run creates a new snapshot and leaves the original immutable.

The active project ID, name and product family are persisted in QSettings across desktop restarts. A project ID is regenerated when the user chooses New project.


## Frequency response data and graph comparison (D43)

New calculation snapshots include raw frequency-domain point arrays in result JSON:

- `frequencySweep[]`: `frequency_Hz`, `phasePeakCurrent_A` (√2 × maximum per-phase branch RMS current) from the 151-point logarithmic AC circuit sweep.
- `impedanceScan[]`: `frequency_Hz`, `busImpedance_Ohm`, `filterImpedance_Ohm`, `sourceImpedance_Ohm` from the 501-point logarithmic impedance scan. This series is empty when source R/L is not supplied or the impedance scan is not verified.

The desktop Calculation page plots phase peak current and bus impedance against logarithmic frequency. The Calculation history table supports selecting exactly two snapshots; the comparison control overlays their selected metric on common axes and includes both snapshot identifiers in the legend. Metrics can be switched between bank current and bus impedance without recomputing either design.

Snapshots created before D43 do not contain frequency point arrays. They remain readable, but graph comparison reports that curve data is unavailable rather than reconstructing or inventing samples. All stored values are numeric SI values with frequency in hertz, current in amperes and impedance in ohms. Snapshot engine metadata includes the `frequencyPlotSchema=frequency-response-v2-resonance-isat-v1` identifier.


## Resonance bandwidth and inductor saturation reference (D44)

The impedance-scan bus-impedance curve is inspected for local parallel-resonance maxima. For each bounded peak, the displayed resonance zone is the frequency interval where the bus-impedance magnitude remains above the peak divided by √2 (-3 dB bandwidth). The band is shaded on both the phase-peak-current and bus-impedance charts. A band is not fabricated when the scan has no valid source R/L data, no local maximum, or no crossings within the scanned range.

The current chart now stores and plots the maximum per-phase series-branch peak current: √2 multiplied by the largest phase RMS branch current at each sweep frequency. This makes the plotted quantity comparable to a manufacturer peak-current rating per phase, when the datasheet defines that rating on the same basis.

The user may enter an inductor Isat reference in A peak per phase and a source/evidence reference. The value is persisted in the immutable input snapshot and restored with historical inputs. A red dashed line shows the entered reference. It is explicitly a rating comparison only, not a computed magnetic saturation limit. Datasheet Isat values defined as DC bias current at a specified inductance drop are not directly comparable and must not be entered as peak-current ratings. Core geometry, magnetic path, B-H curve, DC bias, temperature-dependent saturation and inductance roll-off are not modelled; missing Isat remains NOT_VERIFIED.

## Magnetic B-H sweep snapshot data (D46)

Calculation input snapshots now also store:
- Per-phase equivalent core effective area, mean magnetic path, total air gap and winding turns.
- User-supplied B-H points as H [A/m] and B [T], plus the material source/provenance reference.
- The separately entered manufacturer peak-current Isat reference and its evidence reference.

Result snapshots store magneticSweep[] with frequency_Hz and peakFluxDensity_T, plus optional knee current and knee flux-density values derived from the supplied B-H curve. The current-frequency plot uses a separate B-H knee-current marker; it is not merged with the manufacturer Isat reference.

The B(f) series is stored only when every AC sweep operating point is within the measured B-H curve. An out-of-domain point invalidates the complete B(f) series rather than leaving a misleading partial curve. Historical snapshots without these fields remain readable and are not backfilled with inferred magnetic data.
