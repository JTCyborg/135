# P135.008 — 3D CAD workspace specification

Status: architecture and interaction contract. The CAD backend has an initial semantic assembly presentation tree with stable IDs, core/bobbin/winding grouping, visibility and transparency state, validation, and a flattened display-item adapter. The adapter emits leaf B-Reps only, applies ancestor visibility and composites transparency, avoiding duplicate display of parent compounds. The desktop CAD page now embeds an initial Windows Qt-hosted OCCT AIS viewport with Iso/Front/Top/Side/Fit all commands, left-drag rotation, middle-drag pan, wheel zoom and click selection. It is deliberately empty until verified physical geometry is supplied; the current engineering form has magnetic effective values but not the mechanical dimensions required by `ReactorPhysicalGeometry`. Assembly tree controls, selection properties, clipping/section plane and actual geometry-builder integration remain pending.

## 1. Purpose and source of truth

The workspace presents the validated physical reactor model built by `Project135Cad`. The engineering/domain model remains authoritative for electrical, magnetic and thermal quantities. CAD edits are explicit physical-geometry edits and must never silently mutate solver inputs. All CAD lengths are expressed in millimetres at the OCCT boundary; domain values remain SI.

The workspace must distinguish three states:
- `NOT_PROVIDED`: required physical dimensions/material data are absent.
- `NOT_VERIFIED`: data exists but the relevant validation has not passed or cannot be performed.
- `VALID`: the relevant geometric checks passed. This does not imply standards compliance or manufacturing release.

No default dimensions, densities, conductor layouts, mounting holes or lamination details may be invented to make a model appear complete.

## 2. Workspace layout

The desktop page is a resizable three-region workspace:
- Left dock: assembly tree and visibility controls.
- Centre: OCCT 3D viewport.
- Right dock: selected component properties, dimensions, material and validation.
- Bottom panel: build diagnostics, warnings and export history.

The viewport owns camera/navigation and AIS presentation only. Geometry construction, BOM, material properties and export logic remain in CAD services, not in Qt widget code.

## 3. Assembly tree and visibility

Stable component IDs, not translated display names, identify assembly nodes. Initial semantic groups:

| Stable group ID | Display name | Expected contents |
|---|---|---|
| `core.laminations` | Core laminations | Individual lamination/packet solids when the physical packet model exists; otherwise the current validated core segment solids must be labelled as a simplified core model |
| `core.spacers` | Non-magnetic air gaps / spacers | Explicit non-magnetic spacer solids only when thickness/material/placement are supplied; an air gap is a void, not a spacer |
| `winding.bobbins` | Bobbin / insulation | Bobbins and separately modelled insulation parts |
| `windings.L1`, `windings.L2`, `windings.L3` | Windings L1/L2/L3 | Independently selectable phase winding parts; envelope-only geometry must be labelled as an envelope, never as detailed conductor geometry |
| `mechanical.clamps` | Clamping brackets & terminals | Clamps, tie rods, brackets, terminals and leads when their physical definitions exist |

Every node supports visibility. Transparency is an independent per-node presentation property (0–100%) and must not alter the B-Rep or exported solid. Parent visibility cascades to children; a child can be individually hidden while its parent remains visible. A missing component is shown as unavailable/NOT_PROVIDED, not as an empty successful part.

The assembly tree must preserve stable IDs across rebuilds so user visibility and selection state can be restored where the same component still exists.

## 4. View and section controls

Required camera commands: `Iso`, `Front`, `Top`, `Side`, `Fit all`. Orthographic views must use consistent model axes and a documented projection convention.

Section view is a viewport clipping operation defined by a plane (origin and normal), initially offered through the centre of the selected limb. The user can move/reverse the plane and toggle the section. Section display must expose actual model voids, bobbin walls, winding envelopes and spacers where those solids exist. A clipping plane is not a geometry edit and must not affect STEP/DXF export unless the user explicitly requests a section drawing.

Later drawing generation must use OCCT section/intersection and HLR services; it must not export a screenshot as DXF.

## 5. Dimensions, mounting and mass

The properties dock displays:
- overall bounding dimensions `W × D × H` in mm, derived from the assembly B-Rep bounding box;
- mounting pitch X/Y and hole diameters only when mounting datums/features are defined;
- core, winding, insulation/hardware and total mass only when each included solid has a verified material density and a valid volume.

Mass must be computed from per-component B-Rep volume × assigned density, with an itemized breakdown. Missing density makes the corresponding mass and total mass `NOT_VERIFIED`; do not silently omit unknown parts from a value labelled Total mass. A bounding box is geometric metadata, not a substitute for drawing-defined mounting dimensions.

## 6. Manufacturing exports

### STEP
Export the full selected assembly with component hierarchy/names and units. Use OCCT STEPCAF/XCAF document support when the assembly/BOM layer is available, rather than flattening the assembly to an anonymous compound. Export must report component count, unit, file path and validation result. Round-trip tests must re-import the file and compare component identity/count, B-Rep validity and volume/bounding dimensions within declared tolerances.

### DXF
DXF is a drawing/2D manufacturing export, not a substitute for STEP. Initial supported outputs should be explicitly scoped:
- lamination profile only when packet/lamination geometry and manufacturing drawing data are verified;
- spacer profile only when the spacer is a real supplied component with a defined outline and thickness;
- later orthographic/section drawings with dimensions and annotations.

Each DXF export records units (mm), scale (1:1 for manufacturing profiles), layer names, source component IDs and revision. Do not generate lamination flat patterns from the current seven-solid core envelope: it does not yet represent individual laminations or a verified step-lap packet construction.

## 7. Additional production workflow

The workspace architecture reserves commands for:
- Exploded view, driven by explicit assembly placements and reversible presentation offsets;
- BOM, with stable part number, description, material, quantity, mass status, source/revision and validation status;
- geometric validation: null/invalid solids, zero/negative volume, component interference, clearances and bounding-box checks;
- manufacturing validation: insulation distances, air-gap spacer fit, winding clearances, mounting interfaces and tolerances only when corresponding rules/data are available.

A geometrically valid B-Rep is not proof of insulation coordination, thermal suitability, magnetic performance, standards compliance or manufacturing readiness.

## 8. Implementation sequence

1. **P135.008.6 — Assembly presentation model:** initial implementation added in `assembly_presentation.hpp/.cpp`: stable component IDs, core and phase hierarchy, OCCT shape references, per-node visibility/transparency, tree validation, and `collectAssemblyPresentationDisplayItems()` for viewport-ready leaf solids. Parent visibility suppresses descendants; transparency is composited through the hierarchy. Group compounds are excluded to prevent duplicate rendering. The model is a CAD-layer adapter; no Qt types leak into it. Core parts are explicitly marked simplified and windings as envelopes. Exploded transforms, material appearance, clamps, spacers and persisted UI state remain open.
2. **P135.008.7 — Qt/OCCT viewport:** initial Windows implementation now creates an OCCT OpenGL driver, V3d viewer/view and AIS context inside a native Qt child window. It accepts flattened presentation display items, applies transparency, and provides Iso/Front/Top/Side/Fit all, left-drag rotation, middle-drag pan, wheel zoom and click selection. Remaining: connect a verified `ReactorPhysicalGeometry` source, synchronize tree visibility/transparency and selected-object properties, implement section clipping, and verify high-DPI/device-loss/resource lifecycle on Windows Debug/Release.
3. **P135.008.8 — Properties and validation:** B-Rep bounding box, per-part properties, material-density assignment and honest NOT_VERIFIED mass reporting.
4. **P135.008.9 — STEP assembly exchange:** XCAF/STEP export and round-trip tests.
5. **P135.010 — Drawings and DXF/PDF:** projection, HLR, sections, dimension associativity, title blocks, BOM and verified manufacturing profiles.

Each step requires focused CAD tests and Windows Debug/Release desktop builds. Until a step is implemented and built, the UI must label it planned/unavailable rather than expose a non-functional button.
