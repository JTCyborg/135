# P135.004 — Thermal Engine

## Status

The first independent steady-state thermal-node solver is implemented in `Project135::Thermal`.

## Model

For each independent component node:

```
T_component = T_ambient + P_loss * R_theta
```

Where:
- `T_ambient` is absolute ambient temperature in kelvin;
- `P_loss` is total steady-state dissipated power in watts;
- `R_theta` is component-to-ambient thermal resistance in kelvin per watt.

The model is intentionally a single-node estimate. The thermal resistance must correspond to the actual mounting, heatsink, enclosure, airflow and orientation. It must not be guessed from package type.

## Natural-convection correlation (first implementation)

Project135::Thermal::analyzeVerticalPlateNaturalConvection() implements the Churchill–Chu correlation for an isolated, isothermal vertical plate.

Inputs are deliberately explicit:
- exposed area and vertical characteristic length;
- ambient and surface temperatures (film temperature is calculated);
- air thermal conductivity, kinematic viscosity, thermal diffusivity and Prandtl number;
- source references for fluid properties and geometry;
- explicit confirmation that the surface is in unobstructed, quiescent ambient.

The solver returns Rayleigh/Nusselt numbers, heat-transfer coefficient and the corresponding single-surface thermal resistance. It rejects missing provenance, non-positive inputs, an unconfirmed boundary condition and Rayleigh numbers outside 1e-1…1e12. Output is always marked PRELIMINARY.

This is a reusable correlation primitive, not yet an automatic winding thermal model. A winding is not a single isolated vertical plate: its exposed faces, orientation, inter-phase gaps, enclosure blockage, support conduction and surface-temperature distribution must be assembled from the actual construction. Radiation and solid conduction are not included. Until those surfaces and paths are derived, the desktop workflow must not feed this result into a winding temperature prediction or claim PASS/FAIL.

## Required evidence

A node can receive PASS or FAIL only when all of the following are present:
1. non-negative total component loss and a source reference for that loss;
2. positive component-to-ambient thermal resistance and its source reference;
3. maximum permitted component temperature and its source reference.

If any required value or source reference is absent, the result is NOT_VERIFIED and no estimated temperature is emitted. A negative temperature margin is FAIL; zero or positive margin is PASS within this limited model.

## Current limitations

- Independent nodes only: mutual thermal coupling and shared heatsinks are not solved.
- Steady state only: no thermal capacitance, warm-up/cool-down transient or cyclic duty.
- No spatial temperature field or local hot-spot calculation.
- Reactor copper/core losses are not yet derived automatically; they must be supplied by a validated electrical/loss model or measurement.
- The filter bridge transfers Harmonics Engine damping-resistor I²R losses into thermal nodes and now also derives capacitor ESR losses from per-branch, per-harmonic RMS current.
- Capacitor ESR supports a frequency curve with log-log interpolation between adjacent source points. Extrapolation is prohibited. A scalar ESR is accepted only when the component data explicitly confirms frequency independence.
- Capacitor ripple-current assessment compares total RMS branch current with the supplied component rating. Frequency and temperature correction factors are not yet applied, so this is a preliminary rating check and not a compliance decision.
- Capacitor thermal estimates use the selected component's maximum temperature and dataset revision. Installation-specific component-to-ambient Rθ remains mandatory for PASS/FAIL; if absent, the result is NOT_VERIFIED.
- Component values marked `UserDefined` are not accepted as verified rating/temperature evidence. In addition, manufacturer/measurement origin alone is insufficient: the immutable component snapshot must explicitly carry `designReleaseStatus = VERIFIED`. Catalog listings and starter records marked `NOT_VERIFIED` remain NOT_VERIFIED even when their source is a manufacturer catalog. This gate is independent of numeric/domain validation.
- Desktop filter workflow now resolves the selected capacitor/resistor by immutable SQLite revision ID, constructs validated domain catalog entries, and calls both thermal bridges after a successful harmonic study. Installation Rθ, its evidence reference, and ambient temperature are editable inputs. A component revision is not silently replaced by a newer revision during a calculation. The selected revision IDs and harmonic-study timestamp are included in the calculation context; persistent saved-study provenance is a subsequent step.
- No automatic thermal derating curves or standards compliance decision.
- PASS means only that the supplied single-node estimate is below the supplied temperature limit; it is not product certification.

2. Add reactor copper/core losses from the Winding and Magnetic Engines.

4. Add coupled thermal resistance networks for component-to-component and component-to-ambient paths.

6. Add thermal FEM adapter and correlate analytical estimates against measured reference cases.


### Horizontal plate free convection

The thermal library also provides McAdams correlations for an isolated heated
horizontal plate. The caller must provide the exposed area, exposed perimeter,
surface and ambient temperatures, film-temperature fluid properties, geometry
and fluid-property source references, and explicit confirmation of unobstructed
quiescent ambient. Characteristic length is calculated as exposed area divided
by exposed perimeter.

For a heated face upward, the implementation uses Nu = 0.54 Ra^(1/4) for
1e4 <= Ra < 1e7 and Nu = 0.15 Ra^(1/3) for 1e7 <= Ra <= 1e11. For a heated
face downward, it uses Nu = 0.27 Ra^(1/4) for 1e5 <= Ra <= 1e10. Results
remain PRELIMINARY. These isolated-plate correlations must not be applied to
blocked or enclosed winding faces without a validated enclosure/duct model;
they also exclude radiation, supports, adjacent phases and forced airflow.



### Propagating natural-convection evidence into a thermal network

`makeNaturalConvectionAmbientLink` converts the calculated thermal resistance
to an ambient conductance and retains the correlation name plus geometry,
fluid-property and boundary-model source references. Current isolated-plate
correlations are always marked preliminary at this interface. The thermal
network may solve the numerical temperatures, but a preliminary ambient link
forces `modelProvenanceComplete=false` and node assessments remain
`NOT_VERIFIED`; caller-provided status text cannot promote the correlation
to a released model. A separate model-validation/release process is required
before any future boundary model can be treated as verified.
